# Meta P7-CLAUDE — paridade do Claude Code no painel

**Destino de planejamento — 03/10/2026:** backlog sem fase ou versão comprometida, conforme [bkl-06](../bkl-06-integracoes-agentes.md). As evidências, implementações, limitações e gates abaixo são preservados; esta integração não compõe o aceite da Fase 5. Novos trabalhos dependem de repriorização explícita.

**Estado: adiada no backlog; distribuição comercial não homologada.** Objetivo: entregar no painel Agente IA recursos equivalentes aos liberados para GitHub Copilot usando exclusivamente a CLI oficial Claude Code. A autenticação e a cobrança ficam sob controle dos métodos nativos da CLI; não há modo Anthropic API dentro desse caminho nem fallback automático. Esta meta não bloqueia P7-COP e não libera capacidades sem política, evidência ou autorização comercial.

## Decisões mantidas

- Usar exclusivamente autenticação e execução do Claude Code oficial no painel, preservando seus métodos nativos. O custo/cobrança depende do método efetivamente selecionado. Não ler credenciais, copiar tokens, usar endpoints privados ou fazer fallback para Anthropic API. O provider HTTP Anthropic legado permanece fora do catálogo Desktop e do painel.
- Restringir por segurança destino, transporte e sessão Claude Code hospedeira sem confundir esses controles com o método de autenticação. Os bloqueios de ambiente remanescentes e sua compatibilidade comercial precisam de confirmação formal da Anthropic.
- Manter a allowlist nativa atual do Claude Code e completar o conjunto de ferramentas do produto no plano/registry MCP, sob permissões, consentimento, confirmação e auditoria existentes.
- Manter a persistência oficial de transcrições do Claude Code para permitir `--resume`. `KeepHistory=false` continua significando sem persistência local do KapibaraStudio; não apaga as transcrições oficiais do Claude. A UI/documentação precisa comunicar essa diferença.
- Não ler nem apagar credenciais Claude legadas do cofre do KapibaraStudio por meio do painel CLI. Conversas Claude antigas não migram automaticamente para sessões/transcrições Claude Code, nem as transcrições oficiais são importadas automaticamente para o histórico local.
- Preservar os providers, catálogos, políticas, configurações e testes específicos do Copilot. Compartilhar contratos e registry somente onde já são deliberadamente comuns.

## Etapas e critérios de aceite

1. **Mapeamento e isolamento — concluído em revisão estática:** manter esta matriz junto ao inventário Copilot existente; provar por `git diff --name-only` e revisão que providers/runtime/testes Copilot não foram alterados por esta entrega. Localizar regras por provider nos adapters Claude/Copilot, sem copiar mecanicamente a política específica Copilot.
2. **Contratos Claude — parcialmente concluído:** manter seleção limitada pela allowlist, delegar elegibilidade por plano à CLI, exigir plano por turno e preservar a allowlist nativa atual. Tools do produto passam pelo registry MCP e por permissões/consentimento/grants; Mongo document reads usam consentimento separado. Schema sampling fica fechado em todos os providers até que exista aprovação local ligada à UI. `EndConversation` é tratado como controle oficial com ferramentas nativas ou MCP. Exigir testes para tools não registradas, plano/permissões alterados, revogação e erros de sessão.
3. **Integração de runtime — pendente:** executar no Windows com conta Claude Pro e CLI oficial, sem reutilizar credenciais pelo app. Aceitar somente evidência observável de conversa e streaming, ferramentas do produto com decisão humana, proposta, cancelamento e retomada após reinício. Usar workspace/MongoDB descartáveis; nunca selecionar testes que atuem em dados do usuário.
4. **Interface e privacidade — parcialmente implementado, inspeção pendente:** a configuração de conta já exibe aviso de que a CLI grava transcripts no local oficial e que KapibaraStudio não os lê/apaga (`AgentSettingsViewModel.TranscriptNotice`). Permissões Claude mantêm as ferramentas nativas editáveis e exibem consentimento Mongo separado, desligado por padrão. Schema sampling continua oculto até existir consentimento local delimitado. Verificar catálogo/status após refresh e mensagens localizadas para modelo fora da allowlist; inspecionar fluxo de proposta/aprovação e estados de erro no Desktop.
5. **Regressão e distribuição — pendente:** rodar as suítes unitárias compartilhadas e Windows completas autorizadas pelo projeto; confirmar que os testes Copilot continuam passando. Documentar separadamente qualquer limitação comercial Anthropic e não representar build/teste local como homologação da assinatura.

## Evidência atual e limites

O provider de Claude, configuração de turno e integração MCP são contratos locais implementados; testes usam doubles/fakes. A CLI oficial preserva os métodos nativos de autenticação e decide elegibilidade, limites e cobrança; a allowlist local só limita nomes de modelo aceitos pelo produto. O host mantém bloqueios separados para destino, transporte e sessão hospedeira. `--system-prompt-snapshot off` mantém o prompt dinâmico atual também em `--resume`; `EndConversation` continua tratado como controle oficial com ferramentas nativas ou MCP. O teste `LocalHistoryOptOutKeepsClaudeOfficialTranscriptAndResumeBehavior` comprova que `PersistProviderSession=false` não injeta `--no-session-persistence` e que a segunda mensagem usa `--resume`. O fluxo não lê/apaga credenciais Claude legadas do cofre nem migra automaticamente conversas antigas; não há evidência de migração ou importação. Em 02/10/2026, restore locked/build passaram, build sem avisos/erros, Infrastructure.Agents.Tests **263/263**, UnitTests **3.363 aprovados, 20 ignorados**, integração focada Claude/permissões **95/95**, composição MCP **6/6** e `git diff --check` sem erros. Os PNGs de permissões Claude pt-BR claro/escuro em 660×760 e 960×760 foram inspecionados. Schema sampling permanece fechado até a UI capturar consentimento local delimitado. Esses resultados não comprovam execução real da CLI ou cada método nativo, cobrança, streaming, tools MCP oficiais, aprovação, retomada após reinício nem distribuição comercial.

O cenário explícito `ClaudeCodeRealCliTests.RealCliReadsSyntheticWorkspaceContextThroughProductionMcpRegistry` já prepara uma chamada de contexto sintético pelo proxy MCP de produção; exige `SLOP_CLAUDE_MCP_SERVER` e sessão oficial autenticada e não foi executado nesta entrega. MongoDB, aprovação nativa, UI real, conta Claude em uso e termos comerciais não estão homologados. A meta Linux tem um limite separado: não executar CLI/login/MCP/MongoDB/GUI em máquinas Linux, conforme [meta Linux Copilot/Claude](../../phases/phase-05-v0.9.0/meta-linux-copilot-claude.md).
