# Homologação manual das contas Codex/ChatGPT e Claude

**Roteiro planejado e ampliado em 27/09/2026. Nenhuma execução manual foi registrada e nenhum caso está aprovado.** Para Claude, valem os [casos C-01..C-45 do modo Claude Code](#casos-do-modo-claude-code-assinatura), que substituem H-01..H-17 nesse provider; H-01..H-17 continuam para o 7B. Os casos C não cobrem H-01..H-17 por analogia automática: cada caso verifica comportamento próprio do modo Claude Code. O código do provider e parte do polimento CLP existem no checkout, ainda sem homologação com conta própria; 7B continua pendente. Falta de conta, binário ou SO gera bloqueio identificado, sem concluir a prioridade por API Key. Registrar separadamente provider, SO, versão e plano.

## Regras invariáveis

- **Somente manual.** Login por conta nunca é automatizado com credenciais reais, nem roda em CI, script agendado ou agente de desenvolvimento. Testes automatizados usam fixtures sintéticas do protocolo e não substituem este roteiro (ver [11](11-plano-de-testes.md#login-por-conta-homologação-manual)).
- **Contas do próprio usuário**, criadas e pagas por ele. O Slop não fornece contas, créditos ou intermediação de cobrança. Preferir uma conta dedicada a testes, sem dados de trabalho.
- **Dados sintéticos.** MongoDB descartável com documentos fictícios e um canário identificável (por exemplo `CANARIO-HM-<data>`), sem dados reais. Nunca conectar um banco de produção.
- **Nenhum segredo na evidência.** Senhas, códigos de verificação, tokens, cookies, e-mail/ID da conta, caminhos de perfil do SO e URIs MongoDB completas são mascarados antes de qualquer captura ser guardada. O agente de desenvolvimento nunca recebe essas credenciais; ele só lê o registro sanitizado.
- **Aprovação é do executor.** Um caso só passa com resultado observado e registrado; ausência de conta, SO, binário ou rede gera `Bloqueado`, nunca aprovação por mock. Falha em qualquer caso de segurança mantém o respectivo acesso desabilitado: H-08, H-09, H-10, H-12, H-16 para o 7B; **C-06, C-08, C-09, C-10, C-11, C-12, C-14, C-15, C-24, C-25, C-26, C-27, C-28, C-29, C-31 e C-32 para o modo Claude Code** (bloqueiam GCL-3/GCL-5, não apenas o caso individual).
- **Dono do gate.** Resultados alimentam AC-05 (Codex), AC-06 (Claude), AC-07 e AC-08 em [12](12-criterios-de-aceite.md), mas por si sós não os aprovam: a revisão de código, o QA automatizado e a decisão registrada sobre suporte oficial continuam necessários.

## Casos do modo Claude Code (assinatura)

**Acrescentado em 25/09/2026 para o bloco [Integração Claude](23-integracao-claude.md); ampliado com os casos C-19..C-32 (cobrindo as lacunas identificadas na revisão independente e as propostas CP-01..CP-08 do [threat model — documento 22](22-threat-model.md)) e, na revisão de escopo do mesmo dia, com C-35..C-36 (leitura com/sem pasta de workspace); nenhuma execução.** Para Claude, estes casos substituem H-01..H-17: H-09 (ferramentas nativas desativadas) e a parte de transcript de H-16 não se aplicam ao modo Claude Code por decisão do usuário; as demais intenções estão cobertas abaixo. **Revisão de escopo de 25/09/2026 ([ADR-054 revisada](../../10-decisoes-arquiteturais.md#revisão-de-25092026-mesma-data-decisão-posterior-do-usuário--riscos-residuais-do-threat-model-não-aceitos-escopo-revertido)):** os casos C-08, C-09, C-10, C-11, C-26, C-32 e C-33 foram reescritos para verificar que `WriteFile`/`DeleteFile`/`ExecuteCommand`/`Network` ficam **ausentes por construção** (fora da allowlist `--tools`), não mais aprovadas por chamada; C-09 passa a verificar leitura repetida sem prompt em vez de "sempre nesta sessão", que não existe mais para essas categorias. C-19..C-32 rastreiam as ameaças e propostas manuais do documento 22 (coluna "Rastreio 22"). Mesmas regras invariáveis: execução só pelo usuário, conta própria, dados sintéticos, nada de token/e-mail na evidência. Os comandos `claude auth login/logout` são executados pelo próprio usuário (diretamente ou pelos botões do Slop); agentes de desenvolvimento não os executam com conta real.

Pré-condições adicionais: versão do Claude Code registrada (`claude --version`, origem de instalação oficial); pasta de trabalho sintética como cwd; canários sintéticos inofensivos de hook, MCP de projeto e regra `permissions.allow` preparados para C-15; ambiente inicial **sem** `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` nem `apiKeyHelper`.

## Higiene e encerramento

Ao terminar: encerrar sessões, executar logout, remover itens de teste do cofre, remover somente os artefatos do diretório de teste isolado, após verificar seu caminho e preservar a evidência sanitizada, revogar a autorização da conta de teste se desejado e guardar somente a evidência sanitizada. Falhas encontradas viram pendências no [plano](10-plano-de-implementacao.md) e na [memória](../../memory/phase-7.md); jamais são resolvidas alterando asserções ou relaxando o gate. O resultado agregado só é levado a [12](12-criterios-de-aceite.md) com data, commit e SO.
